# کراچی مرغی سپلائی — لیجر (MERN)

`لیجر_ستمبر_2026_کراچی.xlsx` کا مکمل متبادل — روزانہ شیٹ، گاہک کا بقایہ، سپلائر/آڑتی کھاتہ، بینک اسٹیٹمنٹ اور پارٹی لیجر۔

> **سب سے اہم بات:** تمام فارمولے صرف backend میں ہیں — `backend/src/utils/formulas.js`۔
> فرنٹ اینڈ کوئی حساب نہیں کرتا، وہ ہر بار سرور سے نتیجہ منگواتا ہے۔

---

## چلانے کا طریقہ

### 1. ضروریات
- Node.js 18 یا اس سے اوپر
- MongoDB (مقامی یا MongoDB Atlas)

### 2. Backend

```bash
cd backend
cp .env.example .env      # پھر .env میں MONGO_URI اور JWT_SECRET بدلیں
npm install
npm run verify            # فارمولوں کی تصدیق — ڈیٹابیس کی ضرورت نہیں
npm run seed -- --fresh   # ستمبر 2026 کا اصل ڈیٹا ڈالے
npm run dev               # http://localhost:5000
```

### 3. Frontend

```bash
cd frontend
cp .env.example .env      # عام حالات میں خالی ہی ٹھیک ہے
npm install
npm run dev               # http://localhost:5173
```

### 4. لاگ اِن
| یوزر | پاس ورڈ | رول |
|---|---|---|
| `admin` | `admin123` | ایڈمن — سب کچھ |

## فارمولوں کی تصدیق

`npm run verify` آپ کی اپنی Excel فائل کے 5 دنوں کے نتائج سے ہمارے انجن کا موازنہ کرتا ہے:

```
✅ کامیاب: 70    ❌ ناکام: 0
```

یعنی وزن، رقم، اوسط ریٹ، بقایہ، ریکوری، خرید، ایکسسز/شارٹ، بچت، خرچا، صافی بچت اور کوسٹنگ ریٹ — سب Excel سے بالکل ملتے ہیں۔

---

## فارمولے (Excel سیل → کوڈ)

### روزانہ شیٹ — گاہک کی لائن (rows 4–66)
| Excel | مطلب | کوڈ |
|---|---|---|
| `D = B × C` | رقم = وزن × ریٹ | `rowAmount()` |
| `E` | پچھلے دن کا `I` | `previousClosingFor()` |
| `F = D + E` | ٹوٹل رقم | `computeEntry()` |
| `H = 100000+25000+…` | ریکوری کی قسطیں | `rowRecovery()` |
| `I = F − H` | نیا بقایہ | `computeEntry()` |
| `B = 931.7+222.5` | ایک دن میں کئی لوڈ | `rowWeight()` |

### ٹوٹل (row 67)
`B67/D67/E67/F67/H67/I67 = SUM` · `C67 = D67 ÷ B67` (اوسط ریٹ) → `computeSaleTotals()`

### خرید / سپلائی (rows 71–78)
`A71 = C × D` (ریٹ × وزن) · `A78 = SUM` · `D77 = B67 − کل خرید وزن` (منفی = شارٹ) → `computePurchases()`, `excessShort()`

### منافع (rows 80–83)
`A80 = D67` · `A81 = A80 − A78` (بچت) · `A82 = خرچوں کا جمع` · `A83 = A81 − A82` (صافی بچت)

### کوسٹنگ (G72–G76)
```
G72 = شارٹ وزن × بنیادی ریٹ      ← شارٹ کی مالیت
G73 = A82                        ← دن کا خرچا
G74 = G72 + G73
G75 = G74 ÷ B67                  ← فی کلو خرچہ
G76 = G75 + بنیادی ریٹ            ← کوسٹنگ ریٹ
```
→ `computeCosting()`

> **نوٹ:** آپ کی Excel میں 1 اور 2 ستمبر کو کوسٹنگ کی بنیادی ریٹ ہاتھ سے 258 اور 290 لکھی گئی تھی، جب کہ اُس دن خرید کی ریٹ 266 اور 282 تھی۔ اسی لیے `baseRate` اور `shortWeight` دونوں قابلِ ترمیم رکھے گئے ہیں — آپ جو ڈالیں گے، وہی چلے گا؛ خالی چھوڑیں گے تو خودکار حساب ہوگا۔

### کھاتے
| کھاتہ | فارمولا |
|---|---|
| پارٹی (عمران شیخ) | `بقایہ = پچھلا + جمع − خرچہ` |
| بینک | `بقایہ = پچھلا + جمع کرواے − نکالے` |
| سپلائر / آڑتی | `رقم = وزن×ریٹ` · `ٹوٹل = رقم + پچھلا بیلنس` · `بقایہ = ٹوٹل − دیے` |

## زنجیر (cascade) — سب سے ضروری خوبی

Excel میں `E4 = پچھلے دن کا I4` تھا۔ اگر آپ 2 ستمبر کا وزن بدلتے تو آگے کے سارے دن ہاتھ سے ٹھیک کرنے پڑتے۔

یہاں ایسا نہیں: کسی بھی پرانے دن کی شیٹ محفوظ کرتے ہی **اُس کے بعد کی تمام شیٹوں کے بقایہ خود دوبارہ حساب ہو جاتے ہیں** (`utils/recalc.js` → `cascadeFrom()`)۔ گاہک کا اوپننگ بیلنس بدلنے پر بھی پوری زنجیر دوبارہ چلتی ہے۔

## Excel ایکسپورٹ — منتخب تاریخوں کی فائل

**Reports** صفحے پر تاریخ کی رینج منتخب کر کے **"ایکسل فائل ڈاؤن لوڈ کریں"** دبائیں۔
بنتی ہوئی `.xlsx` فائل میں شامل ہوتا ہے:

- اُس دورانیے کے تمام دن — ہر دن ایک الگ ٹیب (`DD-MM-YYYY`)، بالکل اصل فائل جیسا
- پارٹی لیجر (جتنی پارٹیاں اُس دورانیے میں ملیں)
- بینک کھاتے کی اسٹیٹمنٹ
- دونوں سپلائر (آڑتی) کے کھاتے

**سب سے اہم بات:** ہر خانہ **زندہ فارمولا** ہے (`=B4*C4` وغیرہ)، عدد نہیں۔ فائل کھول کر
اگر کوئی نمبر بدلیں تو باقی سب خود دوبارہ حساب ہو جائے گا۔

> اس فیچر کے لیے `exceljs` پیکج درکار ہے — پہلے سے `package.json` میں شامل ہے،
> `npm install` کرتے وقت خود آ جائے گا۔

## Vercel پر Deploy کرنا (Backend + Frontend دونوں)

**دو الگ Vercel پروجیکٹ بنائیں** — ایک backend کے لیے، ایک frontend کے لیے (ایک ہی repo میں دو فولڈر ہیں، دونوں کو الگ الگ root رکھ کر امپورٹ کریں)۔

### Backend

1. Vercel پر «New Project» → یہی repo منتخب کریں → **Root Directory: `backend`**
2. Vercel کی Environment Variables میں یہ سب شامل کریں (یہ `.env` فائل کی جگہ لیتی ہیں — `.env` خود Vercel پر نہیں جاتی):
   - `MONGO_URI` — مکمل Atlas connection string (`mongodb+srv://user:pass@cluster.../murgi_ledger?...`)
   - `JWT_SECRET` — کوئی لمبی random سٹرنگ
   - `JWT_EXPIRES` = `30d`
   - `CLIENT_URL` — frontend کا Vercel URL (نیچے frontend deploy کرنے کے بعد ملے گا)
   - `RATE_LIMIT` = `300`
   - `NODE_ENV` = `production`
3. Deploy کریں۔ `backend/vercel.json` پہلے سے موجود ہے — یہ ہر درخواست کو `api/index.js` کی طرف بھیجتا ہے (سرور لیس فنکشن)۔
4. Deploy مکمل ہونے پر ایک URL ملے گا، جیسے `https://murgi-backend.vercel.app` — یہی frontend کے `VITE_API_URL` میں جائے گا۔

### Frontend

1. «New Project» → **Root Directory: `frontend`**
2. Environment Variables میں: `VITE_API_URL` = `https://murgi-backend.vercel.app/api` (اوپر والا backend URL + `/api`)
3. Deploy کریں — Vercel خود `npm run build` چلا کر `dist/` سرو کر دے گا۔
4. اب backend کے پروجیکٹ میں واپس جا کر `CLIENT_URL` کو اسی frontend URL پر اپڈیٹ کریں (ورنہ CORS بلاک کرے گا)۔

<div class="box warn">
<b>دو باتیں جو سرور لیس ماحول میں مختلف ہیں:</b>

- **Rate limiting** میموری میں رہتی ہے — سرور لیس میں ہر «کولڈ اسٹارٹ» پر ریسیٹ ہو سکتی ہے، یعنی حد بندی مقامی سرور جتنی دقیق نہیں ہوگی (کام بہرحال کرتی ہے)۔
- **Excel ایکسپورٹ** (بڑی تاریخ کی حد) میں وقت لگ سکتا ہے — Vercel کے مفت پلان میں فنکشن کی حد 10 سیکنڈ ہے۔ اگر بڑی رینج ایکسپورٹ کرتے ہوئے ٹائم آؤٹ آئے، تو مختصر رینج آزمائیں یا Vercel کے فنکشن ٹائم آؤٹ کی سیٹنگ بڑھائیں (Pro پلان)۔
</div>

## اندراج کی سہولتیں

- **وزن** میں `931.7+222.5` لکھیں تو دو لوڈ الگ الگ محفوظ ہوں گے، جمع خود ہو جائے گا۔
- **ریکوری** میں `100000+25000+8000` لکھیں تو ہر قسط الگ ریکارڈ ہوگی۔
- «سب پر ریٹ لگائیں» بٹن — جن لائنوں میں وزن ہے، سب پر ایک ہی ریٹ۔
- شیٹ «بند» کر دیں تو کوئی ترمیم نہیں کر سکتا (ایڈمن/منیجر کھول سکتے ہیں)۔
- ہر کھاتہ اور رپورٹ پرنٹ کے قابل ہے (براؤزر کا پرنٹ)۔

## پروڈکشن پر لے جاتے وقت

1. `.env` میں `JWT_SECRET` لمبا اور random رکھیں، `NODE_ENV=production`۔
2. MongoDB Atlas استعمال کریں اور روزانہ backup آن رکھیں — یہ کاروباری کھاتہ ہے۔
3. `cd frontend && npm run build` → `dist/` کو کسی بھی static host پر رکھیں، اور `VITE_API_URL` میں asli API کا پتہ ڈالیں۔
4. بینک اور بقایہ کے اعداد حساس ہیں — سرور HTTPS پر ہی چلائیں۔
